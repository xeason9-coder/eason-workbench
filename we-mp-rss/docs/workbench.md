# 信源工作台 0.3.0 · Eason

本地入口：http://127.0.0.1:8768/workbench/ 。先登录再进入自己的客户空间；公网发布由部署任务单独验收。账号初始化、旧数据迁移和代理配置见 [部署交接](deployment-handoff.md)。

## 日常操作

- 左侧新建、切换客户；客户可归档，并在客户管理的“已归档客户”中恢复。管理员和成员默认都只访问自己的客户空间。原始文章不因客户归档而删除。
- 来源管理：已接入 WeRSS 原有微信公众号后台名称搜索（需管理员或运营者扫码登录）。工作台保存该登录后优先用它搜索；也可从已有来源、微信读书书架选择，或一次性填写公众号标识、带 `__biz` 的文章长链接。用户在修正配置后完成真实后台扫码；名称搜索已找到“项有所成”，随后新增两篇正文并通过 Eason 检索。微信读书官方 `wrk-` 搜索密钥是可选入口：文档支持公众号搜索，但本次目标及对照查询均返回电子书等类型，已显示明确异常，不视为“公众号不存在”。短链接无法直接解析；新来源须经过实际采集验证。
- 来源分类、暂停更新、手动更新分别作用于客户的绑定。同一公众号绑定多个客户时共享原始文章，客户的收藏、人工关键词、备注和排除记录独立。
- 近七天是滚动时间视图；积累文章库保留旧文章，不需要复制或搬运记录。
- 搜索标题、主题词、后台检索词和正文。明确位于文末的推荐区不作为正文匹配依据；全文仍然保留。标题命中优先，正文提及继续保留并标明，不因未打标签而漏掉文字命中。
- 文章卡片最多显示 3 个主要主题词。配置模型后，新文章采集完成会自动根据标题与可读正文提取主题词，并保留最多 15 个去重后的检索词（含主要主题词）。已有文章在“设置与连接 → 主题关键词”补全；相同内容复用结果，内容变更后才重新提取。此操作会将文章文字传给 DeepSeek 并按 API 用量计费；用户人工修改的主题词继续优先。
- 提取任务逐篇保存，最多一批 100 篇。出错会停止本轮，已完成结果保留，未完成的可再次补全；进度只在当前进程中保存，服务重启后重新补全会跳过已有结果。全文很长时最多取首尾合计 24,000 字符，不声称覆盖图片中的文字。
- 文章详情展示原有段落、强调、表格和配图。文章放在禁用脚本的独立阅读区；发布者脚本、表单和嵌入播放器不运行。图片由浏览器从原文的微信图片域名加载，没有制作完整离线图片副本。原文入口保留。
- 文章详情可收藏、编辑关键词和备注、排除或恢复。CSV 导出跟随当前客户、关键词、来源和时间筛选，阅读量未知留空。
- 每日任务在服务运行期间执行，默认北京时间 09:00。旧演示任务 `pmi-daily` 已停用，由工作台任务统一管理，避免重复采集。新来源加入后会自动参与下一次更新；不会自动补齐停机超过七天的全部历史。
- 设置中可更新微信读书扫码登录。页面显示已保存凭据不等于当前凭据仍有效，以实际采集结果为准。
- DeepSeek 密钥只存本机服务端的 `data/workbench-settings.json`；页面不回显、不写浏览器缓存。设置中保存后测试连接，再发送一个问题验证真实生成。也可由 `DEEPSEEK_API_KEY` 环境变量管理。
- 对外助手名称为 **Eason**，页面、对话标签、公开配置响应和错误提示不显示模型供应商；不声称底层模型为自研。模型实际名称只留在服务端配置。对话例子：`PMI，最近七天 PMP 相关主题有哪些？`。助手调用 DeepSeek 解析条件，再检索已入库文章并整理回答，卡片里的日期与原文链接由数据库提供。每次最多返回 10 条，明确显示匹配总数。无资料时说明未找到；不虚构阅读量。
- 对话按账号与客户隔离，最多保留最近 24 条，保存在当前浏览器标签页的会话缓存；退出登录时清除本人对话缓存。清空按钮只清空当前客户对话，文章数据保存在服务端。

## 数据在哪里

`data/db.db`：文章、公众号、客户、私有选文记录、主题词、采集记录，以及账号、会话与 AI 用量。0.3.0 增加 owner 归属；旧客户表在备份后事务迁移，将全局重名限制改为同一账号内不重名。旧数据须明确认领给管理员，成员初始为空。`data/wx.lic` 同时保存公众号后台与微信读书凭据；`data/workbench-settings.json` 保存工作台和模型设置；`config.yaml` 是底层配置。这些文件及备份均需保密。

飞书不是运行依赖。以后需要团队表格协作时，可按客户同步指定字段；不必再把飞书作为检索中转。

## 升级与恢复

1. 先运行 `backup`，它使用 SQLite 在线备份并检查数据库完整性，结果在 `data/backups/<时间-编号>/`。备份含密钥和登录状态，必须私密保存。备份不包含程序代码，程序版本另由 Git 保存。
2. 修改前记录 Git 提交号，保留可运行旧版本。升级只替换本次列出的程序文件；不要覆盖 `data/`、`config.yaml` 或本机密钥。不要直接用上游最新版覆盖定制版。
3. 后续增加数据库字段时，先在备份副本验证兼容性和迁移，再操作实际数据。0.3.0 的 SQLite 约束调整需要事务重建客户表；先停旧进程，使用交接中的认领命令，逐项核对原有数据。
4. 停止旧进程，再启动新版本；Windows 后台进程号保存在 `data/server.pid`，它可能是 Python 启动器，停止时需核对对应子进程。云端部署后应交给服务管理器统一启停，届时再提供对应命令。
5. `check` 只核对公开健康状态和版本；登录工作台后核对客户、文章总数及采集时间，再验证检索和增量采集。
6. 程序回退时切回保存的 Git 版本。若数据也需要恢复，必须先停止服务，额外保留当前数据库，再恢复对应备份的 `db.db` 与匹配配置；不可把旧数据库文件直接覆盖到正在运行的服务。备份复制/恢复在临时数据上有自检，真实业务库尚未执行恢复演练。

.venv\Scripts\python.exe -X utf8 -m unittest tests.test_weread_session core.wx.model.test_weread_mp
node tests/check_workbench_ui.cjs

## 后续渠道与云部署边界

- 现有原始文章字段（标题、正文、来源、时间、原文链接）可供其他渠道复用；客户和来源绑定、文章选择记录、查询与对话是独立层。
- 当前真正接通的采集器只有微信读书公众号通道。新增网站、RSS 或其他平台，需要补对应的来源校验与采集入口，再统一写入文章库；各渠道的可访问性、授权、频率、去重标识要单独实测。不提前添加空接入器或声称平台都能抓。
- 0.3.0 已接入账号、服务端客户归属、HttpOnly 会话、同源写入限制及 AI 额度。公网须配置单一 HTTPS origin，保持单 worker，并完成目标服务器的代理、账号隔离与备份验收；本地通过不等于公网已通过。
- 本地关键词检索会扫描候选正文；规模增大后可增加清洗后的全文索引，不用重写页面和客户数据模型。
- 标签改善检索覆盖和结果排序，不代表已建立全文索引，也不保证标签越多检索越快。纯图片中的文字尚未 OCR；模型标签可能需要人工修订。
- 现有接口：`GET /workbench/api/articles`、`POST /workbench/api/chat`，均需要工作台会话及归属校验。默认关闭上游 RSS、旧管理 API、`/static` 和 `/api/docs` 等无客户隔离的入口。

采集代码基于 [rachelos/we-mp-rss](https://github.com/rachelos/we-mp-rss)，保留原 MIT 许可证。DeepSeek 接口与模型名称依据其[官方文档](https://api-docs.deepseek.com/)实现；模型单价和可用性以服务商当前控制台为准。

### 公众号二维码配置修正（2026-11-10）

对照上游 `driver/wx.py` 确认工作台直接复用 `WX_API.GetCode()` 与 `wxLogin()`。扫码超时发生在共享浏览器驱动等待腾讯二维码图片期间，不是工作台自行生成了一种二维码。

已将公众号登录、恢复登录及切换账号时创建的控制器统一设为 `apply_anti_crawler=False`，避免把采集用的全局请求头及页面脚本注入登录页。此模式同时保持浏览器默认的 HTTPS 验证与 CSP；其他采集控制器的默认行为保持原样。新增两项无网络、无浏览器进程的回归检查，并通过已有登录接口检查，共3项通过。修正依据是原组件提供的开关及其兼容性注释，不能据此断言已经找到二维码超时的唯一根因。受工具网站安全策略限制，本轮未再次访问腾讯登录页、未自动发起二维码请求；真实扫码仍待用户在正常使用环境中验证。
